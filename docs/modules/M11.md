# Module M11 — App do Entregador (`apps/courier-android` Kotlin/Compose, `apps/courier-ios` Swift/SwiftUI)

## 1. Scope & Architecture
- **Native dispatch controllers**:
  - Android: `src/main/kotlin/com/ideliveryfood/courier/dispatch/CourierDispatchController.kt`
  - iOS: `Sources/CourierApp/CourierDispatchController.swift`
- **Availability**: a courier can only go online with GPS permission granted; denial surfaces `courier_gps_permission_denied_notice` and keeps the courier offline. No coordinates are fabricated.
- **Address privacy**: incoming offers are always stored with `fullCustomerAddress = null` (even if the payload contains one); the full address is set only from the server's acceptance response.
- **Offer expiry**: acceptance after `expiresAt` is rejected client-side; the server remains authoritative (`acceptDeliveryOfferTransactional`).
- **Offline behavior**: location samples are queued locally while offline; delivery completion is **blocked** while offline (`OFFLINE_COMPLETION_BLOCKED` / `.offlineCompletionBlocked`) — the app never marks a delivery as completed locally.
- **Proof of delivery**: 4-digit customer OTP required; final verification happens server-side.
- **i18n**: `en` default, `pt-BR` selectable; 100% key parity across `values/strings.xml`, `values-pt-rBR/strings.xml` and `Localizable.xcstrings`.

## 2. Verification Notes
- Kotlin (`CourierDispatchControllerTest.kt`) and Swift (`CourierDispatchControllerTests.swift`) unit tests are included but require Gradle/Android SDK and Xcode toolchains respectively; they are **not** executed by `pnpm test` in this Windows workspace.
- Compose/SwiftUI screens binding these controllers to UI are not yet implemented.
