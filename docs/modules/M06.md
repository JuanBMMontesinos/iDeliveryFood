# Module M06 — App Mobile do Cliente (Android Nativo em Kotlin/Compose & iOS Nativo em Swift/SwiftUI)

## 1. Scope & Architecture
- **Native Android (`apps/customer-android`)**: Independent Kotlin + Jetpack Compose implementation (`CustomerMarketplaceController.kt`, `SecureSessionStore.kt`).
- **Native iOS (`apps/customer-ios`)**: Independent Swift + SwiftUI implementation (`CustomerMarketplaceController.swift`, `KeychainSessionVault.swift`).
- **Zero Hybrid Wrapper**: No React Native, Flutter, or WebView shell is used. Both native apps consume the shared `/v1` API contract and share 100% localized string key parity (`en` default + `pt-BR`).

## 2. Core Invariants Verified
1. **Single-Store Cart & Store-Switch Confirmation**: Adding an item from a second store while the basket is non-empty returns `requiresStoreSwitchConfirmation = true` and preserves the original basket until the customer explicitly confirms.
2. **Offline Stale-Cache Protection**: When offline (`setOfflineMode(true)`), cached catalog data is flagged with `isCachedDataStale = true` (`offline_stale_cache_banner`) and checkout submission is blocked (`canSubmitOrder = false`).
3. **Honest PSP Status (`BLOCKED_MISSING_CREDENTIALS`)**: When external payment provider credentials are absent, checkout surfaces `checkout_psp_blocked_notice` and disables order payment submission rather than faking payment capture.
4. **Secure Session Vault & Deep Link Allowlist**: Access/refresh tokens are stored exclusively in encrypted platform storage (`Android Keystore` / `iOS Keychain`), and deep links are restricted to `ideliveryfood-customer://auth-callback`, `ideliveryfood-customer://orders`, and `ideliveryfood-customer://stores`.
5. **Cross-Platform Build Transparency**: Android XML and iOS `.xcstrings` catalogs and source trees are validated in CI; full Xcode/iOS compilation requires a macOS runner and is never simulated on Windows.
