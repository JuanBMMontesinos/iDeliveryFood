# Module M14 — Logística, Despacho e Console Operacional (`apps/admin-web`, `apps/api`, `packages/domain`)

## 1. Scope & Architecture
- **Delivery Task & Offer Creation (`POST /v1/logistics/offers`)**:
  - Restricted to `operations`/`tech_admin` staff (scope MFA rules apply).
  - The task is created with `dropoffFullAddress = null`; offers expose only `dropoffNeighborhoodOnly`, pickup store, distance and fee. The 4-digit proof-of-delivery code is stored only as a SHA-256 hash.
- **Transactional Offer Acceptance (`POST /v1/logistics/offers/:offerId/accept`, `acceptDeliveryOfferTransactional`)**:
  - Rejects offline couriers (`COURIER_OFFLINE`), other couriers' offers (`403 DELIVERY_OFFER_FORBIDDEN`), non-`OFFERED` or expired offers, and tasks that already have an active courier (`409 DELIVERY_TASK_ALREADY_ASSIGNED`).
  - Database invariant: `uq_delivery_assignments_one_active` guarantees a single active assignment per task.
  - The full customer address is revealed **only** in the acceptance response.
- **GPS Telemetry (`POST /v1/logistics/location-samples`, `evaluateCourierLocationSample`)**:
  - Couriers can only report against tasks assigned to them (`403`); unknown task IDs return `404`.
  - Samples older than 120 s, more than 30 s in the future, or with accuracy worse than 150 m are flagged `isStaleOrLowAccuracy` so uncertain GPS is never the sole proof. 24 h retention (`expiresAtIso`).
- **Proof of Delivery (`POST /v1/logistics/tasks/:taskId/complete`)**:
  - Assigned courier or `operations`/`tech_admin` only; constant-time 4-digit OTP check (`verifyDeliveryConfirmationCode`); `409` for invalid OTP, missing OTP, or already-completed task.
- **Dispatch Console (`buildLogisticsDispatchConsoleModel`)**:
  - When `google_maps`/`mapbox` are `BLOCKED_MISSING_CREDENTIALS`, renders `logistics.maps.fallback_notice` with deterministic Haversine distance/ETA — no simulated map tiles or fake courier positions.

## 2. Known Limitations
- Tasks/offers in `apps/api` use in-memory stores when no repository adapter is supplied; Supabase tables and RLS policies (`delivery_tasks`, `delivery_offers`, `delivery_events`) are in place.
- Automatic offer fan-out / courier ranking is not yet implemented (offers are created explicitly by ops staff).
