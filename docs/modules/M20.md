## 1. Objetivo e Escopo

O módulo **`M20`** garante entrega confiável e idempotente de notificações (`IN_APP`, `EMAIL`, `PUSH_ANDROID`, `PUSH_IOS`) e webhooks externos assinados via padrão **Transactional Outbox** (`public.outbox_events` + `@ideliveryfood/worker`), com templates bilíngues versionados (`en` padrão, `pt-BR` selecionável), recuperação determinística pós-queda de Realtime (`?sinceCursor=`) e higiene imediata de `push_token` na revogação de dispositivo.

## 2. Rotas `/v1` e Worker do Módulo `M20`

| Componente / Rota | Descrição |
| :--- | :--- |
| `GET /v1/me/notifications?sinceCursor=<seq>&unreadOnly=true` | Retorna notificações do usuário autenticado ordenadas por `cursor_seq` e o `latestCursorSeq` para ressincronização sem perda após queda de conexão Realtime. |
| `POST /v1/me/notifications/:notificationId/read` | Marca notificação como lida (`status = 'READ'`, `read_at`) exclusivamente para o destinatário. |
| `POST /v1/me/devices/revoke` | Define `revoked_at`, limpa imediatamente `push_token = NULL` em `public.user_devices` e enfileira evento `security.device_revoked` em `public.outbox_events`. |
| `@ideliveryfood/worker` (`processLiveOutboxBatch`) | Faz polling com `FOR UPDATE SKIP LOCKED` em `public.outbox_events`, renderiza template no idioma do destinatário, respeita opt-out de marketing (`SKIPPED_OPT_OUT`), aplica backoff exponencial (`1s`..`60s`) e move falhas exauridas para `DEAD_LETTER`. |
