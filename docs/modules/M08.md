# Module M08 — Gestor Operacional de Pedidos do Restaurante (`apps/partner-web`)

## 1. Scope & Architecture
- **Dedicated Kitchen Order Console (`KitchenOrderConsoleController` & `GET /v1/stores/{storeId}/orders-queue`)**:
  - Organizes store orders into live operational columns (`NEW`, `ACCEPTED`, `PREPARING`, `READY`, `IN_TRANSIT`, `COMPLETED`, `CANCELLED`).
  - Computes real-time SLA countdowns (`slaDeadlineIso`, `remainingSlaSeconds`, `isSlaBreached`) from authoritative order timestamps (`createdAtIso`, `acceptedAtIso`).
- **Concurrency & Optimistic Locking (`409 ORDER_VERSION_CONFLICT`)**:
  - Every kitchen transition (`ACCEPT`, `REJECT`, `START_PREPARING`, `MARK_READY`, `CANCEL`) sends `expectedVersion` and `X-Idempotency-Key`.
  - When two operators click `ACCEPT` simultaneously, the first transition increments `version` and the second receives a clean `VERSION_CONFLICT` notice (`kitchen.order.conflict_notice`) without corrupting state.
- **Mandatory Rejection Reason**: `REJECT` and `CANCEL` require a structured reason (`>= 3` characters).
- **Audible Alert Consent**: Sound notifications default to `false` and require explicit operator consent (`setAudibleAlertsConsent(true)`).
- **Pause & Reconnect Resilience**:
  - Pausing the store displays `partner.store.paused_banner` and blocks new customer checkouts while keeping all active in-progress orders visible in the kitchen console until completion.
  - `reconcileEventsOnReconnect` deduplicates missed events by event ID and idempotency key after network drops.
